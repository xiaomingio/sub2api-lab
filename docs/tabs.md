# 功能模块说明

Sub2API Lab 的管理台由八个 Tab 组成。页面需要登录；除「余额设置」外，各模块只读取数据，不修改 Sub2API 主库。

## 系统介绍

「系统介绍」是默认入口，用于说明各分析工具的用途和适用场景。它不发起业务数据查询，适合首次进入管理台时确认工作范围。

## 额度趋势

「额度趋势」用于观察上游账号的额度窗口变化：

- 展示账号当前的 5 小时窗口和 7 天窗口使用率、窗口重置时间以及最近一次用量更新时间
- 按 `SUB2API_LAB_TIMEZONE` 的整点展示历史 7 天使用率
- 标记从相邻快照中检测到的 7 天窗口重置
- 支持按时间范围、账号和“仅显示重置”筛选

应用每 30 秒检查一次是否到达配置时区的整点；每个整点最多写入一次 `quota_snapshots`。快照来自 Sub2API `accounts.extra`，不会主动调用 Sub2API 的额度刷新接口。首次使用前需要完成 Lab 数据库迁移。

## 额度分析

「额度分析」把当前账号窗口与本地用量放在同一页面查看：

- 查看各上游账号的 5 小时、7 天窗口和窗口起止时间
- 按用户查看 Token 消耗与费用
- 按账号和模型查看用量分布
- 以小时或每天为粒度查看 Token、实际费用或标准费用趋势

默认范围为最近 7 天。时间范围和粒度只影响查询与图表展示，不会修改原始记录。

## 额度估算

「额度估算」根据小时额度快照和 `usage_logs`，分别估算每个上游账号在当前用量结构下的单模型完整 7 天窗口容量。

可选分析范围为 24、72、168 或 720 小时，默认 720 小时。页面支持选择账号、显示全部模型，以及按输入、输出、缓存读取和缓存创建分别计算。

估算过程会丢弃重置所在整小时、缺失或异常快照和过长的观测间隔，并对所有模型进行稳健非负拟合。结果包含有效覆盖、样本数、额度增量、预测误差、容量区间和稳定性说明。样本不足、模型用量无法区分或波动较大时可能不提供容量。结果只反映样本期内的用量结构，不代表官方固定额度，也不能保证绕过 5 小时限额。

## 使用记录

「使用记录」用于定位具体调用：

- 查看分页后的原始调用记录
- 按时间范围、用户、上游账号、模型、上游接口、入站接口、API 密钥、分组、计费模式、计费类型、请求类型和上游模型是否匹配筛选
- 对模型、分组、接口和用户的记录分布查看饼图
- 自定义每页记录数并切换页码

空选项表示不筛选。记录展示遵循当前数据库可用字段；当 Sub2API 版本缺少某个可选字段时，页面会按当前可读取结构处理。

## 用量统计

「用量统计」按用户汇总所选时间范围内的请求数、输入 Token、输出 Token、缓存 Token、图片 Token、总 Token、标准费用和实际费用。默认范围为最近 24 小时，表格最多展示 1000 行，可按列排序。

其中：

- 标准费用对应 `usage_logs.total_cost`
- 实际费用对应 `usage_logs.actual_cost`，包含 Sub2API 分组倍率
- 日期快捷范围和手动输入的边界均按配置时区解释，并以左闭右开区间查询 `usage_logs.created_at`

## 成本分摊

「成本分摊」根据统计基准计算用户分摊比例，再将实际采购总成本分配给参与用户。实际采购总成本是本月购买 Codex 订阅或相关账号实际支付的金额；该功能不会写入 Sub2API。

支持三种统计口径：

| 统计口径 | 统计基准 | 是否需要月初设置余额 | 适用场景 |
| --- | --- | --- | --- |
| 系统余额 | `max(初始系统余额 - 当前系统余额, 0)` | 需要 | 账号统一发放系统余额，月底按余额消耗分摊 |
| 实际费用 | `usage_logs.actual_cost` 汇总值 | 不需要 | 按 Sub2API 实际扣除口径分摊 |
| 标准费用 | `usage_logs.total_cost` 汇总值 | 不需要 | 按模型官方价格口径分摊 |

只有“系统余额”口径依赖初始系统余额。未勾选的用户会显示在结果表中，但统计基准按 `0` 处理，不参与分摊。实际费用和标准费用口径不需要设置初始余额，可以设置开始时间、结束时间，并筛选上游账号；未选择账号表示不过滤。

实际费用按 Sub2API 分组倍率后的 `usage_logs.actual_cost` 统计；标准费用按模型官方价格对应的 `usage_logs.total_cost` 统计。页面支持人民币和美元作为实际采购总成本的货币单位。

分摊公式为：

```text
用户分摊比例 = 用户统计基准 / 所选用户统计基准总额
用户应承担成本 = 用户分摊比例 * 实际采购总成本
```

例如，三位成员的统计基准分别占 `50%`、`30%` 和 `20%`，实际采购总成本为 `1200` 元，则三人分别承担 `600` 元、`360` 元和 `240` 元。

使用系统余额口径时，按以下顺序操作：

1. 月初在「余额设置」中为参与用户设置相同且充足的初始系统余额，例如 `5000`。
2. 月内通过 Sub2API 正常使用 API，由 Sub2API 按自身计费规则扣除系统余额。
3. 月底在「成本分摊」中选择“系统余额”，填写初始系统余额和实际采购总成本。
4. 确认分摊结果后，在「余额设置」中设置下个月的统一额度。

余额设置会覆盖当前余额，而当前余额是计算本月系统消耗的依据，因此必须在成本分摊完成后执行下月余额设置。

## 余额设置

「余额设置」用于批量把所选普通用户的 Sub2API 系统余额设置为目标值，并显示当前余额与账号信息。

该功能需要配置 `SUB2API_BASE_URL` 和 `SUB2API_ADMIN_API_KEY`。写入通过 Sub2API Admin API 的余额设置接口完成，使用 `operation: "set"`；Sub2API 负责同步余额调整历史和缓存。未配置管理员 API Key 时，页面仍可查看余额，但不能执行写入。

管理员 API Key 具有完整管理员权限，只应放在真实环境变量文件或部署平台的密钥配置中。

## 数据与时间范围

页面时间使用 `SUB2API_LAB_TIMEZONE`，默认值为 `Asia/Shanghai`。手动输入和“今天”“本月”“上月”等快捷范围会先按该时区生成边界，再转换为绝对时间点查询数据库。查询采用 `created_at >= start` 且 `created_at < end`。
